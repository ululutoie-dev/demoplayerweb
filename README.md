# Demo Player (Web / PWA版)

自分で制作したWAVデモ音源をiPhone Safariで確認するための、シンプルな個人用音楽プレーヤーのWebアプリ版です。
外部サーバーは一切使用せず、音源はすべてiPhone内のIndexedDBに保存されます。

## ファイル構成

```
index.html      アプリ本体（React + JSX、CDN経由でReactを読み込み）
db.js           IndexedDBラッパー（音源Blobとメタデータの保存・取得・削除）
sw.js           Service Worker（アプリの外枠だけをキャッシュ。音源データはキャッシュしない）
manifest.json   PWA用マニフェスト
icon-192.png    ホーム画面アイコン
icon-512.png    ホーム画面アイコン（高解像度）
```

## 使い方（iPhoneでの公開・設置方法）

このアプリは**静的ファイルだけ**でできているので、Node.jsサーバーやビルド工程は不要です。
ただし、Service Worker・IndexedDB・`getUserMedia`系のAPIはブラウザの制約上、**HTTPS（またはlocalhost）配信でないと正しく動作しません**。`file://` で直接開くと一部機能が制限されます。

以下のいずれかの方法で配信してください。

### 方法A: 無料の静的ホスティングを使う（一番簡単）

1. [GitHub Pages](https://pages.github.com/)、[Netlify](https://www.netlify.com/)、[Vercel](https://vercel.com/) などに、このフォルダ内の5ファイル（index.html, db.js, sw.js, manifest.json, icon-192.png, icon-512.png）をそのままアップロードする
2. 発行されたURL（例: `https://your-app.netlify.app/`）にiPhoneのSafariでアクセスする
3. 共有ボタン（□に↑）→「ホーム画面に追加」でアイコンが追加される
4. 以降はホーム画面のアイコンから起動できる（フルスクリーン表示）

※ 音源データはNetlifyやGitHub側には一切送信されません。ホスティングサービスはHTMLファイルの配信のみに使われ、WAVファイル自体はiPhone内のIndexedDBにローカル保存されます。

### 方法B: 自分のMac経由でローカル配信する

1. Macでこのフォルダに移動し、`python3 -m http.server 8000` などで簡易サーバーを起動
2. MacとiPhoneを同じWi-Fiに接続
3. iPhoneのSafariで `http://（Macのローカルip）:8000/index.html` を開く
   - ただしこの方法は `http://` (非HTTPS) になるため、Service Workerやホーム画面追加後の一部動作が制限される場合があります
   - 継続利用するなら方法Aを推奨します

- [ ] ミニプレーヤーの再生／一時停止ボタンで、ライブラリ画面のまま再生を操作できる
- [ ] 再生／一時停止ができる
- [ ] 前の曲／次の曲に移動できる（ライブラリの並び順どおり）

## 設計上のポイント（要件との対応）

- **音質変更なし**: `db.js` の `addTrack` は、選択された `File` オブジェクト（Blob）をそのままIndexedDBに保存します。デコードや再エンコードは一切行っていません。再生も `URL.createObjectURL(track.blob)` で作ったURLを `<audio>` タグにそのまま渡すだけです。
- **クラウド不使用**: 外部サーバーへの通信は一切ありません。すべての処理はブラウザ内で完結します。
- **永続化**: IndexedDBに保存されたデータは、Safariを閉じても、iPhoneを再起動しても残ります（ユーザーが明示的にSafariの「履歴とWebサイトデータを消去」を行わない限り）。
- **再生キュー**: ライブラリの表示順をそのまま再生キューとして使っています。表示順は初期状態では取り込み日時の新しい順ですが、各行の↑↓ボタンで手動並び替えが可能で、並び替えた順序がそのまま再生順・保存順になります。
- **容量エラー**: IndexedDBへの書き込み時に `QuotaExceededError` が発生した場合、画面上部にエラーメッセージを表示します。WAVを圧縮・変換することでの回避は行わず、不要な音源の削除を促す設計です。

## 既知の制約（iOS Safari特有の事情）

- **バックグラウンド再生**: iOS Safari（PWA含む）では、画面ロック後や他アプリ切り替え後に再生が途中で止まる場合があります。これはWebKit側の制約によるもので、Webアプリの実装では完全な回避ができません。そのため、ロック画面やコントロールセンターからの再生操作には依存せず、アプリに戻った際にライブラリ画面下部の**ミニプレーヤー**（曲名タップで再生画面へ、右側のボタンで再生／一時停止）からすぐに操作を再開できるようにしています。確実なバックグラウンド再生が必要な場合は、先に作成したネイティブiOSアプリ版をご利用ください。
- **ストレージ上限**: iOS Safariは、端末の空き容量やブラウザの設定により、IndexedDBに保存できる総容量に制限があります（一般的には端末の空き容量に対する一定割合）。WAVは非圧縮のため、数十曲程度で数GBに達することがあります。容量エラーが出た場合は、不要な音源を削除してください。
- **ホーム画面版とSafari版のデータ共有**: 同一オリジン（同じURL）であれば、ホーム画面から起動したPWAとSafari本体は同じIndexedDBを共有します。ただし、ホスティング先のURLを後から変更すると、別のデータ領域として扱われる点にご注意ください。

## 曲順の並べ替え（ドラッグ）

- 各行の左端にある「≡」の持ち手を押したまま上下にドラッグすると、曲順を変更できます（iPhoneの指操作・PCのマウス操作の両方に対応）。
- 持ち手の外側は通常どおりスクロールできます。ドラッグ中にリストの上端/下端へ寄せると自動スクロールします。
- 並べ替え結果は `sortOrder` として IndexedDB に保存され、再起動後も維持されます。前の曲/次の曲・自動連続再生もこの順序に従います。
- 持ち手にフォーカスして ↑↓ キーでも移動できます。
- 追加ライブラリは使っていません（Pointer Events を使用）。
